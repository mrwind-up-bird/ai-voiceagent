# Hardening a Rust Desktop App: A 32-Finding Security Audit Journey

Last night, I wrapped up a marathon security remediation session for [Aurus Voice Intelligence](https://github.com/yourusername/aurus), our Rust-based desktop voice assistant. The task? Address all 32 findings from a comprehensive security audit spanning the Tauri backend, React frontend, WebRTC signaling server, and end-to-end encryption layer.

**The scoreboard:** 29 files changed, +1,238/-300 lines of code, and every single test still passing. Here's what that journey looked like.

## The Critical Stuff First

### Command Injection: The Wake-Up Call

**Finding #1** was the kind that makes you sit up straight: PowerShell injection in our text-to-speech system.

Our Windows TTS implementation was doing this:

```rust
// ❌ BEFORE: Vulnerable to injection
let command = format!(
    "Add-Type -AssemblyName System.Speech; \
     $synth = New-Object System.Speech.Synthesis.SpeechSynthesizer; \
     $synth.SelectVoice('{}'); \
     $synth.Speak('{}')",
    voice, text
);
Command::new("powershell").args(["-Command", &command])
```

A user could inject arbitrary PowerShell by crafting malicious text. The fix required base64-encoding the entire command and using `-EncodedCommand`:

```rust
// ✅ AFTER: Injection-proof
fn encode_powershell_command(script: &str) -> String {
    let utf16: Vec<u16> = script.encode_utf16().collect();
    let bytes: Vec<u8> = utf16.iter()
        .flat_map(|&c| vec![(c & 0xFF) as u8, (c >> 8) as u8])
        .collect();
    general_purpose::STANDARD.encode(&bytes)
}

Command::new("powershell")
    .args(["-EncodedCommand", &encode_powershell_command(&script)])
```

This pattern got applied to all three Windows TTS operations: speaking, stopping, and voice enumeration.

### Pairing Codes: From Trivial to Secure

Our device pairing was using 4-character codes from a 24-word dictionary. The math was brutal:

- **Before:** 24⁴ = 331,776 combinations (~18.3 bits of entropy)
- **After:** 999,999 × 256 × 256 = ~16.7 million combinations (~24 bits of entropy)

The new system combines a 6-digit PIN with two words from separate 256-word lists, displayed as `PIN-WORD1-WORD2` (e.g., `483726-CASCADE-THUNDER`). We also added memory zeroing on drop and redacted codes from all logs.

```rust
impl Drop for PairingCode {
    fn drop(&mut self) {
        self.code.zeroize();
    }
}
```

## The High-Priority Fixes

### API Keys: Out of the Command Layer

We were passing API keys as parameters to **15 different Tauri commands**. Every invocation looked like:

```typescript
// ❌ Exposing keys unnecessarily
await invoke('analyze_with_chatgpt', {
  transcript: text,
  agentName: 'summarizer',
  apiKey: settings.openaiKey  // 🚨
});
```

The remediation? Move key retrieval into the backend:

```rust
// ✅ Centralized, secure access
fn get_key_or_error(service: &str, state: &State<AppState>) 
    -> Result<String, String> {
    state.secrets.lock().unwrap()
        .get(service)
        .ok_or_else(|| format!("{} API key not found", service))
}

#[tauri::command]
async fn analyze_with_chatgpt(
    transcript: String,
    agent_name: String,
    state: State<'_, AppState>,
) -> Result<String, String> {
    let api_key = get_key_or_error("openai", &state)?;
    // ... rest of logic
}
```

This eliminated key exposure from the IPC boundary entirely.

### Path Traversal: The Classic Trap

Our audio recording save function was accepting user-controlled filenames:

```rust
// ❌ Vulnerable to path traversal
pub async fn save_recording(
    filename: String,
    app_handle: AppHandle,
) -> Result<PathBuf, String> {
    let path = app_handle.path().app_data_dir()?;
    let full_path = path.join(filename);  // 🚨 ../../../etc/passwd
    // ... save file
}
```

The fix: enforce extensions, canonicalize paths, and validate boundaries:

```rust
// ✅ Constrained to safe directory
pub async fn save_recording(
    filename: String,
    app_handle: AppHandle,
) -> Result<PathBuf, String> {
    if !filename.ends_with(".wav") {
        return Err("Filename must end with .wav".into());
    }
    
    let base_path = app_handle.path().app_data_dir()?
        .canonicalize()?;
    let full_path = base_path.join(&filename)
        .canonicalize()?;
    
    if !full_path.starts_with(&base_path) {
        return Err("Invalid path".into());
    }
    // ... safe to proceed
}
```

## The Cryptography Deep Dive

This was the most intellectually demanding section—and the most fragile.

### The Direction Problem

Our sync protocol uses X25519 + ChaCha20-Poly1305 for end-to-end encryption. The original implementation derived a single symmetric key from the SPAKE2 handshake and used it bidirectionally. **This is dangerous**—nonce reuse becomes trivial if both peers encrypt with the same key.

The fix: direction-specific keys using HKDF:

```rust
// ✅ Separate keys for each direction
pub fn from_shared_secret(
    secret: &[u8], 
    is_creator: bool
) -> Result<Self, CryptoError> {
    let hkdf = Hkdf::<Sha256>::new(None, secret);
    
    let (send_info, recv_info) = if is_creator {
        (b"aurus-c2j", b"aurus-j2c")  // Creator → Joiner, Joiner → Creator
    } else {
        (b"aurus-j2c", b"aurus-c2j")  // Reversed for joiner
    };
    
    let mut send_key = Zeroizing::new(vec![0u8; 32]);
    let mut recv_key = Zeroizing::new(vec![0u8; 32]);
    
    hkdf.expand(send_info, &mut send_key)?;
    hkdf.expand(recv_info, &mut recv_key)?;
    
    Ok(Self { send_key, recv_key, /* ... */ })
}
```

### The Key Rotation Trap

Implementing key rotation exposed a subtle bug. My first attempt rotated keys like this:

```rust
// ❌ Breaks cross-peer decryption
let new_send = rotate_with_info(&self.send_key, b"next-send-key");
let new_recv = rotate_with_info(&self.recv_key, b"next-recv-key");
```

This **seems** logical—rotate your send key, rotate your receive key. But it breaks the protocol! The creator's `send_key` and joiner's `recv_key` are the **same underlying key** (the c2j key). Using different HKDF info strings causes them to diverge.

The fix: rotate based on direction, not send/recv role:

```rust
// ✅ Maintains key agreement
let new_c2j = rotate_with_info(&self.send_key, b"next-c2j-key");
let new_j2c = rotate_with_info(&self.recv_key, b"next-j2c-key");
```

Now both peers derive identical rotated keys for each direction.

### Replay Protection

Added monotonic counter validation:

```rust
pub fn decrypt(&mut self, envelope: &Envelope) -> Result<Vec<u8>, CryptoError> {
    if envelope.counter <= self.max_recv_counter 
        && self.max_recv_counter != u64::MAX {
        return Err(CryptoError::ReplayAttack);
    }
    
    // ... decrypt
    
    self.max_recv_counter = envelope.counter;
    Ok(plaintext)
}
```

Combined with the use of `Zeroizing` for all key material, this brought the encryption layer up to production standards.

## Infrastructure Hardening

### Signaling Server Rate Limiting

Our WebRTC signaling server was wide open. Added per-IP rate limiting:

```rust
const MAX_JOINS_PER_MINUTE: u32 = 5;
const MAX_RELAYS_PER_MINUTE: u32 = 100;

async fn handle_join(
    state: &ServerState,
    addr: SocketAddr,
    // ...
) -> Result<(), Box<dyn Error>> {
    let mut limiters = state.rate_limiters.lock().await;
    let limiter = limiters.entry(addr.ip()).or_insert_with(RateLimiter::new);
    
    if !limiter.check_join() {
        return Err("Rate limit exceeded".into());
    }
    // ... process join
}
```

Also added:
- 10-minute room TTLs (auto-cleanup)
- Identity validation on relays (only relay to known peers)
- 64KB message size limits
- Encrypted post-handshake messages (heartbeats, key rotation)

### Content Security Policy

Locked down the Tauri webview with a strict CSP:

```json
{
  "security": {
    "csp": "default-src 'self'; connect-src 'self' https://api.openai.com https://api.anthropic.com wss://signal.aurus.app; script-src 'self' 'wasm-unsafe-eval'; style-src 'self' 'unsafe-inline'"
  }
}
```

Any new API integration now requires an explicit CSP update—defense in depth.

## Lessons Learned

### 1. Worktree Isolation Isn't Always Persistent

I initially spawned AI agents with `isolation: "worktree"` to parallelize the fixes. The agents completed their work, but their worktree branches were cleaned up on shutdown—all changes vanished. 

**Lesson:** For critical remediations, work in the main tree or ensure worktree branches are explicitly preserved before agent termination.

### 2. Cryptographic Protocols Are Unforgiving

The key rotation bug (different HKDF info strings) would have been catastrophic in production. It passed all unit tests because each test only exercised one peer's perspective.

**Lesson:** Cryptographic tests need to simulate **both sides** of the protocol and verify round-trip correctness.

### 3. Security Debt Compounds

Several findings (API keys in commands, path traversal, CSP) were "we'll fix it later" items from early development. Fixing them simultaneously required coordinating changes across 8 files.

**Lesson:** Security-critical items (auth boundaries, input validation, CSP) should be correct from day one. The refactoring cost grows exponentially.

## The Takeaway

Security remediation isn't just about patching vulnerabilities—it's about understanding **why** each pattern is dangerous and how the mitigations interact with the rest of your system. 

The cryptographic fixes alone touched 6 files and required mental models of bidirectional key derivation, nonce reuse scenarios, and HKDF info string semantics. But that depth of understanding is what separates "adding a check" from "making the system secure."
